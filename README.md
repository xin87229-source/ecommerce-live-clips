# AI 女装直播切片 Skill

首版面向会使用 Codex、能提供本地中文直播回放和准确商品参考的女装电商运营，支持 Windows、单场单款、本地制作与交付。核验同款区间、整理原声候选、制作带字幕的短视频，并交付本地封面、文案和质量记录。合格内容可能只有一条，也可能为零；程序不会为凑数量补造事实。

采用完整仓库＋项目内 Skill 入口：下载完整项目并在 Codex 中打开，让 AI 读取 [Skill 入口](.agents/skills/ecommerce-live-clips/SKILL.md)。不能只复制一个 SKILL.md。当前版本见 [VERSION](VERSION)，已验证内容和待验收项统一见 [验证状态](docs/release-status.md)；新候选按源码清单指纹区分，旧 ZIP 不代表当前代码。

[项目官网](https://azhen-live-clips.jacquesostrovsky.chatgpt.site/) · [独立自测记录](https://azhen-live-clips.jacquesostrovsky.chatgpt.site/testing/) · [安装与首条制作协助](https://azhen-live-clips.jacquesostrovsky.chatgpt.site/service/)

当前仍为预发布候选。自测记录不替代新电脑、外部运营或真实业务验收；协助服务的具体范围见服务页，内容事实与最终成片仍需实际核对。

从[公开 GitHub 仓库](https://github.com/xin87229-source/ecommerce-live-clips)选择 Code → Download ZIP，解压后打开包含 `cli.py` 的目录，再按[首次安装](docs/dependencies.md)配置本机环境。问题可通过 [GitHub Issues](https://github.com/xin87229-source/ecommerce-live-clips/issues)反馈版本、当前阶段和脱敏报错；不要附商家原片、账号信息或私人配置。main 源码下载与正式 Release 分开记录。

当前提供 `basic`（中性商品讲解）和 `apparel`（女装）两套预设。默认成片上限 70 秒，1080×1920、30 fps CFR，保留原声；速度限 1.0～1.5 倍。`apparel` 要求已确认同款原片区间并集至少 20 秒，`basic` 不设这个数字门槛。两者都要有完整表达和商品证据。

rc.5 增加 [一次委托制作入口](docs/one-click.md) 与 [按商品选择剪法](docs/apparel-editing.md)：上衣、裤装、连衣裙、半身裙、外套、套装及未知类别共用流程，风格可保留用户原词。Codex负责实际查看、语义选择和内部决策文件，程序执行抽窗、转写、剪辑、审核卡与具备证据后的正式制作，支持核验后的接续。策略支持不等于全类目实测；一键制作不自动授予同款、核词或最终验收通过。

首版仅做本地制作与交付，不上传、不挂车、不排期、不连接店铺账号，不提供完整图形剪辑界面或自动商品识别。需要人工核词时，可生成[本地听审卡](docs/human-review.md)，由运营回听原声并反馈。适用输入限当前处理链可验证的单视频流、单原声音轨、SDR、方形像素媒体。其他操作系统、AI 宿主、品类及异常媒体尚未完成适配验证。

需要先看完整效果时，可制作 [完整待审交付与发帖演练](docs/local-rehearsal.md)：包含选款理由、带机器字幕的视频、真实帧封面、文案、原速问题和本地发帖预览。无需假填审核通过；未核词字幕始终标为待审。模拟只验证本地文件和字段，不操作真实平台。

可直接委托“加速后约一分钟，关键词放大、变色、加粗，给我旧版对比”。Codex根据真实内容扩大同款窗口、选择少量原句关键词并检查实际导出；不会重复片段凑时长，也不会将AI猜测的改字写成已核实字幕。具体时长与强调词服从本次任务，详细边界见[完整演练](docs/local-rehearsal.md)。

## 运行前准备

- Windows，本地 Python，以及可由 Python 调用的 Pillow、faster-whisper 等依赖；具体版本与安装办法以 [依赖说明](docs/dependencies.md) 为准。不要仅凭 Python 版本号推断整套环境兼容。
- 本地 FFmpeg、FFprobe、已经下载的转写模型，以及可显示中文的字体文件。环境检查只读，不自动安装或下载。
- 一个与原素材目录彼此独立的工作目录。真实配置、转写缓存、审查记录与成品都放在工作目录；安装目录只放程序和公共资源。换商家时换工作目录和任务资料，无需改代码。
- 能实际查看画面、听原声并核对商品的人或 AI 工具。脚本校验文件、时间和哈希，不会自行证明画面中的商品与参考一致。

在 Codex 中可以这样委托：

> 请用这套本地模板处理这场中文直播回放，只制作其中的示例商品。我会提供原片、商品参考图和独立工作目录。先核对同款画面与原声，再按真实材料决定能做几条；保留原话，给我可审阅的本地成片、字幕、封面、文案和质量状态。无法亲自听看或核对的部分请标待审，不要当成通过。

这是示意请求，不包含真实文件路径或审核结论。使用者应提供自己的原片和参考，AI 再依据当次任务填写证据。

## 开始使用

1. 按 [快速开始](docs/quickstart.md) 准备本地工具和独立工作目录，运行只读环境检查。
2. 指定原片、商品名称和参考图，新建任务。无商家 SKU 时程序生成与商品参考绑定的本地标识；它不是平台商品 ID。
3. 实际盘点原片，抽取并审核同款窗口。混款整场不能直接当作已确认同款送去转写。将窗口转写映回原直播时间轴后，保留完整材料池。
4. 形成批次草稿，核对覆盖范围、主线、未用素材和差异，再采用可执行方案；制作、字幕与交付分别通过预检和审核。
5. 查看本地包及分项质量记录。技术检查、连续观看、原声试听、商品审核和用户确认是不同结论；缺少真实听看证据时交付待审稿。

每一步的准确命令、最小 JSON 结构和证据来源见 [制作链操作参考](docs/pipeline-reference.md)。旧任务和已存在输出不会自动覆盖；`status` 中的 `UNKNOWN` 应先核实，不应解释为从未提交。工作目录应由操作者自行保管与备份。

先用 [无隐私技术示例](examples/README.md) 检查媒体、中文字幕和本地模型，再用自己的女装原片走 [快速开始](docs/quickstart.md)。需要先比较剪法时，用 [待审粗剪与听审卡](docs/human-review.md)，把实际改动、原片范围与反馈留在独立工作区。运营无需手写 JSON。

目前准备三位目标运营的 [外部试用](docs/external-trial.md)，优先覆盖另一家女装商家；非女装验证放到后续扩展，已有 `basic` 功能保留。这是预发布候选，真实业务全流程、外部独立完成和全新电脑验证尚未完成。
