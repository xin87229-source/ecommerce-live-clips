# 一次委托制作与接续

适用：已完成首次安装的 Windows 用户，在 Codex 中打开完整仓库，提供本地中文直播原片、目标商品参考和独立工作目录。女装各类目共用制作链；具体测试覆盖见 [验证状态](release-status.md)。

用户只需自然语言委托，例如：

> 用本项目 Skill 处理这份直播原片，目标商品见参考图。请自行检查环境、定位商品、选择剪法并完成本地制作。需要核实的原话或同款问题集中给我短片回听；其余步骤自动继续，保留旧版本。

也可追加“最终加速后约一分钟，重要词放大、变色、加粗，保留旧版对比”。Codex应按实际导出长度选择足够的同款内容，并在[完整演练](local-rehearsal.md)中选择原句关键词。用户给出的时长及样式偏好不会授予原话或商品事实的审核通过；没有足够有效内容时说明缺口，不重复旧片凑长。

“一次委托”由 Codex 持续完成判断和程序调用。下面的请求文件由 Codex 创建，运营不用编辑 JSON。当前程序没有独立视觉识别或听审模型；它不能在脱离 AI 判断后自行决定商品与剪法，也不会自动生成虚假的人工通过。首次环境安装仍按 [依赖说明](dependencies.md) 完成。

## Codex 执行循环

1. 检查现有工作区与任务；新任务用 `new-task`，女装使用 `apparel`，局部试跑如实选择 `test`。保留原片和独立参考，不把搭配单品当主商品。
2. 实际查看原片，依据 [商品适配](apparel-editing.md) 定位待检查区间。每个请求窗口不超过120秒，需要更多内容时分为多个明确窗口。窗口由 AI 查看后定位，不要求用户在整场视频中找时间。
3. 在本工作区 `private-context` 保存请求，执行 `auto run`；程序实际抽窗、转写，返回映射、机器词和类目选镜建议。
4. 若结果为 `needs_agent_decision`，由你读取产物、查看画面、在具备能力时听原声并完成下一步。不把该状态直接抛回用户，不把命令清单当成果。
5. 用户要完整效果时，填写[演练说明](local-rehearsal.md)，向请求追加 `rehearsal_spec` 后再次 `auto run`，得到带字幕视频、封面、文案、原速卡和本地发帖预览。只需先比较粗剪时，追加 `cut_spec`，程序自动生成剪片和逐段原速审核卡；也可提供现有格式的 `review_spec` 放入前版对照。两种方式都不自动通过内容审核。
6. 具备真实同款、候选、采用与核词证据后，用现有制作流程完成材料池和批次采用；把正式制作参数追加到请求。统一入口自动执行组合、字幕和交付各阶段，缺少 AI 判断文件时返回准确下一步，由你继续填写。
7. 最终展示实际视频、字幕、封面、文案、验证范围和未通过项目。需要人的问题只提供具体原速片段、版本与时间。自然语言反馈按现有 [听审流程](human-review.md) 原样保存。

## 内部请求格式

路径使用本机真实绝对路径；以下变量和占位符仅作说明。`$Python`、`$Install`、`$Workspace` 来自首次安装，不使用其他电脑的虚拟环境。

```powershell
& $Python "$Install/cli.py" --workspace "$Workspace" auto run "$Workspace/private-context/request.json"
& $Python "$Install/cli.py" --workspace "$Workspace" auto status run-01
```

```json
{
  "run_id": "run-01",
  "task_record": "<本工作区内原片任务run-state.json绝对路径>",
  "windows": [{"start": 30, "end": 90}],
  "category": "tops",
  "style": "auto"
}
```

类别可用 `tops`、`trousers`、`dress`、`skirt`、`outerwear`、`set`、`other` 或明确中文别名。不明确的“裙子”“长裙”“开衫”等回退通用策略，不能仅凭名称猜商品类型。风格可保留用户原词；`auto` 表示依据素材选择，不表示已经识别风格。

追加 `cut_spec` 为本工作区现有剪法JSON的绝对路径，结构见 [待审粗剪](human-review.md)。`review_spec` 可选；省略时自动卡按每段列出原速问题和对应成片范围。生成器只能验证绑定，无法证明剪辑判断正确。

需要完整待审包时，追加 `"rehearsal_spec": "<本工作区private-context中演练说明的绝对路径>"`，说明格式见[完整待审演练](local-rehearsal.md)。它引用的剪法必须绑定本次任务，所有原声及画面窗口、ASR都必须来自本次请求实际执行的结果。可以不提供顶层 `cut_spec`，避免为了完整包先重复生成一份粗剪；同时提供时，二者必须引用同一份剪法文件。

完成后 `auto run` 和 `auto status` 返回 `current_artifact`：包含本次包、可直接打开的 `index` 和视频路径。演练状态仍为 `needs_content_review`，其中 `rehearsal.status` 为 `SIMULATED_NOT_SUBMITTED`。已有的独立 `rehearsal build/check` 继续可用；统一入口只跟踪请求明确绑定的产物，不猜测目录中哪一份是最新版本。

## 收到真实确认后接续正式交付

按 [已审稿交付](reviewed-delivery.md) 保存原始反馈、完整范围与分项确认，并准备有事实依据的封面文案。由 Codex 在同一请求追加 `delivery_spec`，指向当前工作区 `private-context` 中的交付输入，再运行原来的 `auto run`。

`delivery_spec.rehearsal` 必须精确指向本次 `rehearsal` 产生的包。请求须保留 `rehearsal_spec`，不能同时使用下方旧 `production` 分支。程序复用原先抽窗、转写与演练结果，从原片窗口生成正式交付；真实确认、来源和原声/字幕一致性继续由原有 `delivery build/check` 核验。

成功后状态为 `local_delivery_ready`，`current_artifact` 转为正式包、页面和视频；`human_review=prior_accepted_content_preserved` 只表示继承未改内容的原确认。`new_visual_review` 保留新画面检查的实际状态，操作者仍须查看去水印后的画面和新封面，另记检查结果。未上传、未提交，不表示用户看过新文件。

同一请求再次执行只核验并返回已有正式包。若渲染失败，保留失败目录并重试新的尝试目录；不会覆盖旧结果。正式包生成后即使最终报告写入中断，`auto status` 也会核验并找到该包。后来新增阶段有真实失败时仍报告错误，不用已有交付掩盖失败。

## 兼容旧批次制作

旧批次制作使用 `production` 对象，字段依次为：

| 字段 | 真实来源 |
| --- | --- |
| `job` | 本次已完成候选与排序的工作目录 |
| `annotations` | 与已采用条目一致的组合/编辑计划 |
| `source_review` | 实际逐候选审核记录 |
| `task_record` | 本次批次采用后绑定的正式子任务卡 |
| `subtitle_review` | 根据返回的组合及selected材料建立的真实核词与排版记录；可下一次追加 |
| `draft` | 根据返回的准备包及事实建立的封面、标题、文案记录；可下一次追加 |

这些数据使用现有 [制作链参考](pipeline-reference.md) 的格式和门禁。统一入口不自行生成审批、不删编辑字段，不把已有预览拷贝成正式视频。

## 状态与恢复

| 状态 | 谁继续、意味着什么 |
| --- | --- |
| `needs_agent_decision` | Codex继续分析和填写内部决策，不是要求运营操作程序 |
| `needs_content_review` | 已生成待审粗剪或完整演练包；有 `current_artifact` 时直接打开对应入口。原话、同款、最终听感仍待真实审核 |
| `completed_unreviewed` | 正式本地交付文件已生成；不等于人工验收通过或已经发布 |
| `local_delivery_ready` | 本次演练已有真实内容确认并生成正式本地包；新画面及封面检查另记，未发布 |
| `ERROR` | 读取具体错误和原始记录，不重置任务或猜测通过 |
| `needs_resume` | 旧执行记录没有完整结果；先确认运行进程与锁，再由Codex用原请求接续，不能当作已完成 |

同一请求可再次运行，已完成且指纹一致的阶段复用。源片、任务、执行配置、程序版本、策略或已执行的决策变化时须使用新的 `run_id`，保留前次记录。尚未执行的 `cut_spec`、`rehearsal_spec`、`delivery_spec`、`subtitle_review`、`draft` 可以逐次追加；修改已经执行的文件不属于追加。执行过的演练与交付说明不能从接续请求删除，说明、剪法、ASR或输出变化时也不能复用旧包；`auto status` 会再次检查演练及正式包的文件、原始确认和未提交状态。生成成功仅说明文件齐备，审核仍按真实证据分别记录。

升级程序后旧 auto 运行记录仍保留其源码绑定，不改写旧指纹强行恢复。旧版本已完成的独立交付不会被覆盖；需要继续旧 auto 任务时使用它绑定的安装副本，使用新版制作时建立新的 `run_id`。

程序记录每阶段真实产物及文件指纹；普通追加技术日志不作为内容变化。失败尝试保留现场，后续尝试使用新输出目录，不覆盖原片。若提示任务锁存在，先核实是否仍有运行进程，不删除未知锁或同时重复启动。源码更新后的旧任务证据保留，但旧执行状态不能直接冒充新版验证。

阶段失败时，状态报告列出 `failed_stage`、`completed_stages` 和具体错误；输入未变时再次运行原请求，已成功的抽窗不重复制作。任务卡缺少提交字段、状态与提交字段矛盾或已经提交时，统一入口明确报错；即使已有抽窗也不会继续报告“未提交”。先核对原始状态，不能把字段改成false来恢复制作。

120秒上限针对请求区间；实际窗口可能因对齐到原视频帧而多出少量时间。仅在抽取记录和真实媒体共同证明这一差值时接受，不扩大请求上限或放宽异常帧率检查。

## 何时需要用户

用户需要完整待审效果时，Codex 不应只在无字幕粗剪处停下。已有真实抽窗和未核词转写可追加 `rehearsal_spec` 继续[完整演练](local-rehearsal.md)，交付字幕视频、封面、文案和本地发帖预览，同时保持同款、核词及最终验收待审；这不是通过正式门禁的替代方法。

能由现有素材判断的类目、选镜、排版与技术问题由 Codex 处理；不确定时优先换用证据更清楚的素材。听不清原话、无法确认主商品，或当前工具不能实际听原声时，保持待审并提供短问题片。不得为了“一键成功”把机器词写成人工核词，或绕过正式字幕和商品门禁。
