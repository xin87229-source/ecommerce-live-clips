# 女装术语与同音错字

更新：2026-10-28；适用 `apparel`，从 `0.1.0-rc.15` 起随完整 Skill 免费分发。

## 现有词库如何工作

唯一词库是 [subtitle_dictionary.json](../pipeline/subtitle_dictionary.json)。沿用现有本地模型和字幕链，不安装另一套识别服务、不调用云端接口。

- Skill 读取词库分组和局部规则理解女装用词；本地模型仍沿用已验证参数。本轮真实试跑表明把整份词表直接加入模型提示会改变句界并新增错字，因此未启用该方式，不改变旧转写缓存身份。
- 待审演练与正式字幕均可按词库规范化显示文字，原始 ASR、旧缓存和原片保持原样。记录原文、改词、规则、来源句与词库指纹；仍可追溯识别错误。
- `basic` 不套用女装规则。原有通用 `replacements` 保持兼容且默认空；正式字幕的显式人工纠错优先，该句不再叠加自动规范化。

## 哪些自动处理，哪些保留疑点

术语说明用于理解上下文，不作为商品事实证据：

| 词语 | 此流程中的含义/边界 |
| --- | --- |
| 獭兔 | 服装口播中的动物或毛皮名称；拼写纠正不证明实物材质 |
| 绒毛 | 表面细软毛绒；不要和成分比例或实际掉毛情况混为一谈 |
| 穿上身 | 穿着后的状态；“创生”可能另有含义，需局部穿着语境 |
| 背厚 / 背后 | 前者描述体型厚度，后者是方位词；不可全局互换 |
| 版型 / 廓形 | 服装剪裁形成的穿着形态、外轮廓；不据此补写修饰效果 |
| 肌理 / 垂感 / 挺括 | 表面纹理、垂坠感、形状保持感；须与当前口播对应 |
| 门襟 / 肩线 / 下摆 | 衣服开合处、肩部线条、下缘等部位名称 |
| 提花 / 刺绣 | 不同的花纹形成工艺，不能只因同音或画面相似互换 |

初始规则将“塔兔→獭兔”“容毛→绒毛”作为女装术语拼写规范化。“创生”“背后”本身可能有意义，仅在词库列出的完整局部语境中改为“穿上身”“背厚”；“看一下背后”“创生设计”等不改。新词条要区分常见术语与上下文歧义，不把一次听清的结果扩成任何场景的全局替换。

价格、数量、尺码、材质比例、库存、功效、品牌和款号不由词库猜补。写出“獭兔”只代表拼写处理，不能由此认定商品材质，更不能自动添加到封面或销售承诺。没有命中规则不表示原话已正确；命中也不等于实际听审。

Codex 先处理明确规则和用户已确认词语，不对同一文件、同一保留范围反复提问。尚有影响结果的疑点时，结合前后文和实际原声能力集中处理；仍不确定再提供一次带时间的短问题。已确认的词语、同款范围和整片验收分别留证，不要求用户重新证明已经明确的局部事实，也不将局部确认扩大成全场或整片通过。

## 旧转写与字幕时间

为修正旧待审稿，可以保留旧 ASR 预览，用当前程序与新任务号重新生成演练；无需为同音改字重跑整段模型。新转写仍使用原有本地模型参数；词库的作用在 Skill 判断和字幕显示阶段。旧 `auto` 指纹保留，升级代码后的统一流程使用新 `run_id`。

显示文字变化的短句沿用完整原句的起止时间；原机器词时间仅作证据，不冒充新文字的逐词时间。若修改后的长句超出两行且必须分页，程序明确拒绝借用失配词时；重新转写或选择完整短句。没有改词的长句继续复用已有词时分页。

词库、程序、字幕或选段变化都要生成新版本并重核相关检查；旧包和原始反馈保留。整体待审状态及正式交付所需内容确认仍按 [完整演练](local-rehearsal.md) 和 [已审稿交付](reviewed-delivery.md) 执行。
