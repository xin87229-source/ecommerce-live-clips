# 2026-10-28 片尾定格检查误报修复

## 范围与根因

本次仅操作独立公开仓库 `xin87229-source/ecommerce-live-clips`。开工核验 Public、main 与本地同为 `f8b797c`。用户授权修复片尾问题、重测和同步 GitHub；未改雅乔项目或任何网站。

原真实媒体回归为48帧内容＋18帧静音定格，共66帧/2.2秒。旧测试在1.8～2.2秒抽样后要求H.264 CRF18解码的RGB帧逐字节相等，复现得到3种像素内容。实际定格从1.6秒开始，旧检查漏掉前6个定格帧，且未比较最后内容帧。

保留原生产滤镜，仅将对照编码改为无损，1080×1920下最后内容帧47与全部定格帧48～65的摘要完全一致。正常H.264输出缩到16×16后，相对最后内容帧的最大通道差为3/255、平均绝对差不超过0.03125；说明严格字节相等不适用于这份有损输出。错误黑尾虽然尾段自身完全相同，却与末内容帧平均相差约102.50，旧断言会漏检。前面实际内容运动的差异也明显高于压缩误差。

FFmpeg官方对 [tpad](https://ffmpeg.org/ffmpeg-filters.html#tpad) 的定义为补帧，clone模式复用最后帧；本次结论主要依据同输入、同滤镜的实际编码对照，不凭文档推断成片已通过。

## 最小修复与兼容性

修复测试测量位置与契约，复用 `review_cut.render` 和现有真实合成媒体夹具，在无损输出上严格检查最后内容帧＋整个定格区间；正常MP4仍验证实际帧数、静音、音高、源文件与任务状态，并与末内容帧比较有限压缩误差。负对照须拒绝错误定格或运动画面，边界覆盖零帧及最短一帧定格。

公共渲染器由待审剪辑、编辑组合、演练和已审交付复用，后续字幕仍可能再次有损编码。更改生产编码不仅无法保证所有后续文件逐像素一致，还会影响已审稿重建哈希。本次不改生产滤镜/编码、依赖、审核记录、媒体文件或任何恢复门槛，`VERSION`保持 `0.1.0-rc.14`。只新增本任务文档并纳入原精确分发清单。
