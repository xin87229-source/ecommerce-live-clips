# 发布与许可准备

当前定位见[项目规划](project-plan.md)：先完善免费公开的独立 Skill，不涉及任何网站；成熟后再启动开源软件及收费机制。本文定义候选检查范围、许可与执行条件。**当前对外状态的唯一入口是 [release-status.md](release-status.md)**；源码公开、候选包发行、真实外部试用和第三方素材公开许可分别记录。外部试用、建立公开仓库、上传候选和视频发布分别需要明确范围，不能由“本地候选已生成”推导授权。

## 首版的分发形态

意向为 **完整仓库＋仓库内 Skill**，服务 Windows、Python 3.12、中文单场单款的女装电商运营。不能只发一个 SKILL.md，因为它依赖程序、规则与说明。`basic` 保留，非女装验证延后；此轮不做软件 UI、账户系统、店铺接入或自动发布。

通用候选只从 `ecommerce-live-clips` 源码目录选取文件。精确可纳入路径以 [release-files.txt](../release-files.txt) 为准；以下是范围意向，不是递归复制许可：

| 可纳入的通用内容 | 条件 |
| --- | --- |
| README、AGENTS、VERSION、requirements、.gitignore、LICENSE、THIRD_PARTY_NOTICES | 来源和表述已复核；不含本机配置 |
| 项目内 .agents/skills/ecommerce-live-clips/SKILL.md | 相对链接在完整包内可用 |
| pipeline 中通用程序与规则、presets | 不含商家特化资料、原话缓存或本机绝对路径 |
| tests、tools/build_candidate.py、release-files.txt | 测试使用脱敏/合成资料，不携带私有实测证据 |
| docs 中通用安装、流程、免费试用、项目规划与发行说明 | 链接可回查；案例仅保留获准公开的内容 |
| 明确列入白名单的最小示例 | 区分合成技术样例和真实业务样例；无许可的女装素材不纳入 |

以下全部排除：商家原片/窗口/成片、商品参考图、私有听审反馈、运行配置、任务卡、转写缓存、日志、账号和密钥、对话、历史迁移资料、运行时/虚拟环境、模型、字体、FFmpeg 二进制、旧 ZIP、`.git`。通用规则内的示例文字也要复核，不能把真实直播疑词或商家信息当测试数据公开。

真实女装可公开示例缺失时，提供素材规格与合成技术样例，并标注“真实示例尚无公开使用依据”。公开素材权利与内部真实业务验收分别记录：内部三款已审交付的范围见 release-status，不能因此公开对应素材。合成画面、蜂鸣音或测试字幕本身不证明中文原声转写、同款审核或真实成片验收。

暂缓外部试用时，可以继续整理预发布候选、教程、文字案例和免费首次使用交接单；不能把外部/新电脑状态填成通过或升级为稳定版。当前原始公开源码与新本地候选可能不同，给外部用户试用前必须指定同一个候选ID和清单指纹，不混用旧包与新文档。

## 本地候选怎么检查

使用 [候选构建工具](../tools/build_candidate.py) 与精确白名单，参数以工具 `--help` 为准。输出使用项目外尚不存在的新目录；候选标识由 `VERSION` 和源码清单哈希区分，同版本源码变化也不能覆盖旧包。

核对候选中的：

- `SOURCE-MANIFEST.json`：逐文件相对路径、大小与 SHA-256，确认只收白名单文件。
- `CANDIDATE.json`：版本、清单身份与构建信息，明确候选不等于发布。
- `PRIVACY-SCAN.json`：扫描范围、发现和结论；机器无命中也不代替人工逐文件检查。

在解压后的无 Git 副本中检查 Skill 和文档相对链接、CLI 帮助、自动检查以及独立工作区。依赖已在原机器存在的测试只记为“本机独立副本验证”；全新虚拟环境安装和全新电脑验证分别记录，不能互相替代。最后再核对压缩包与解压内容清单。不要直接压缩上一级私人完整项目。

## 第三方与隐私复核

保留 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 中已引入的 ffmpeg-skill 子集来源、改动说明和 MIT 声明。对固定版本上游许可做可回查复核；若当前无法取得上游文件，记录“待核验”，不凭搜索摘要替代。

Python 依赖由使用者独立安装；模型和字体由使用者从官方来源取得。FFmpeg 的许可受实际编译配置影响，不能统称所有 Windows 构建为 LGPL，也不能把项目 MIT 推及 FFmpeg。[FFmpeg 许可说明](https://ffmpeg.org/legal.html) 明确区分 LGPL 基线及启用 GPL 组件的情形。首版不随包分发上述二进制资源；未来若改为捆绑，另做对应版本的许可、通知、源码和分发义务核对。

发布前逐文件查看白名单，检查账号、令牌、Webhook、绝对个人路径、商家名称、原声字幕、商品图片、客户资料和历史日志。发现内容按实际来源处理；删掉文件名不代表文件内容脱敏，`.gitignore` 也不能证明发布包安全。

## 公开前需要落定的事项

| 事项 | 要形成的具体结果 |
| --- | --- |
| 许可证 | 所有者明确选择、版权主体、LICENSE 与第三方通知一致 |
| 发布范围 | 对本次精确白名单与最终文件清单逐项确认 |
| 隐私 | 自动扫描和人工复核都留证；真实示例单独有使用与公开依据 |
| 试用方式 | [三人试用](external-trial.md) 的包版本、支持范围、反馈材料范围 |
| 下载入口 | 创建后实测可下载与解压，再填写真实 URL；未创建时保留未设置 |
| 反馈入口 | 确定由谁接收、接收什么、是否公开；建立后验证真实地址 |
| 已知限制 | 安装、素材、审核与复用中未通过的项回写 release-status |
| 外发/公开 | 对这一份具体候选确认后再执行，保留实际回执；不把计划写成已发布 |

本地准备可以继续完善；等待许可、反馈入口或外部试用时，不虚构通过结果，也不需要先做 UI、注册系统或支付系统。
