# 完整待审交付与本地发帖演练

运营可以直接要求：“换几份原片测试，交付选款依据、带字幕视频、封面、文案和发帖预览；不实际发布。”Codex 负责检查原片、选择商品和片段、生成内部说明、执行并查看结果。运营不用手写 JSON。

`rehearsal` 用原片窗口重新制作完整待审包，适合正式核词和同款审核尚未完成时比较实际效果。视频和封面带待审标记，字幕完整保留机器识别文字；不补猜原话，也不修改正式任务审核状态。它不能替代 `combine → subtitle → package → quality` 的正式业务交付。

## 先选素材，再决定做什么

- 多款测试优先换原片场次、商品或商家，记录各候选的选用理由和不选原因。不同裁切、速度或文件名不算新商品覆盖。
- 对照画面和口播判断主讲商品。主播穿着整套服装，不意味着每件都是本条主商品；没有明确证据时写“候选，待确认”。
- 先排除切换款式、被遮挡、私人通知和无关对话。整场抽样不能证明整场检索完成，几帧截图不能证明连续画面合格。
- 同一条的原声和画面必须可追溯到已绑定原片。机器识别明显异常时先找更清晰的替代句；仍不能核实的词保留待审并提供原速问题。
- 测试失败也记录：输入格式不支持、无法确认主商品、只有不完整句或素材质量不足时不强行制造成片。

## 时长、重点词和衔接

用户给出的时长指**变速后的最终导出时长**，包含尾定格。要求“约一分钟”时可按55–65秒寻找完整主线，先估算所需原声，再找同款相邻窗口补足内容。不要靠重复片段、长定格、无关话或未经核实的交易承诺凑时长；可用内容不足则报告缺口。时长目标属于本次委托，不是所有商品的硬规则。

按“展示或搭配引入—关键细节—穿着展示或完整收句”组织，保留动态上身动作与原声整句。优先自然切口和相邻内容；画面衔接应服务商品展示，不默认增加遮挡衣服的转场特效。

可选 `highlight_terms` 由 Codex 从本次实际保留的原句选择，运营不手写。每句最多两处，演练正文48px，重点68px、金黄色、粗体；按放大后的文字宽度排版且不拆开重点词。优先商品名称、部位和搭配词，避免突出疑词、未经证实的材质或效果承诺。高亮只说明视觉重点，不表示该词已经核实。SRT保留原字，ASS负责样式。未提供词表时保留旧式演练行为。

AI可以排查可疑字、重复内容、断句和衔接，不能凭常识把疑词改成另一个词。真正纠错须保留原字、改字、来源区间及核词证据；本入口不接受自填字幕绕过原文绑定。仍无法判断的问题要给出独立原速片段。

rc.8对显示进行有限整理：超过一行时按实际字号均衡为两行；同一剪口、同一原声窗口内，停留不足1.2秒的段可与紧邻段合并，最长4.5秒且不超过两行。仅增加显示分隔空格，原机器段的文字、ID和各自时间保存在 `subtitle_cues[].source_cues` 中；不跨来源、剪口或时间间隙合并。阅读报告列出剩余短停留与每秒超过12字的提示，便于实际查看。阈值不证明语义、口播同步或听感通过，正式核词仍单独完成。

## 程序执行（由 Codex 完成）

先用 `new-task`、`window extract`、`window transcribe-preview` 得到真实任务、抽取记录和未核词转写。剪法沿用 [review-cut 格式](human-review.md)，每段写明作用和具体听审问题；选择完整 ASR 段边界，不能把被剪掉的字仍配在画面上。

在独立工作目录的 `private-context` 中保存演练说明。以下是必填字段，另可加入 `highlight_terms` 词表；路径均由实际运行结果取得：

```json
{
  "schema_version": 1,
  "cut_spec": "F:/clips-work/private-context/draft-cut.json",
  "asr_previews": ["F:/clips-work/private-context/source-windows/task/window/asr-preview.json"],
  "selection": {
    "selected": "本次商品候选",
    "reason": "实际看到的展示动作及选择理由",
    "alternatives": ["另一候选及本次不选的理由"],
    "uncertainties": ["仍需核实的商品身份或内容事实"]
  },
  "title": "与原片画面对应的中性标题",
  "caption": "描述这条内容实际展示什么，不补编材质、销量或效果。",
  "hashtags": ["#女装", "#穿搭"],
  "cover_lines": ["商品候选", "展示主题"],
  "cover_time": 2.0
}
```

`cover_time` 是最终视频内的秒数，程序映回实际原片画面取封面，不取静音尾定格。若字幕原句过长、重叠或被剪口截断，程序拒绝生成；换完整短句，不能借此改写听不清的词。

例如本次原句确实包含“领口”和“牛仔裤”，可加入 `"highlight_terms": ["领口", "牛仔裤"]`。未出现在保留原句中的词会被拒绝。词表、样式、字幕或选段变化都会生成新版本并使旧的对应制作检查失效；旧版保留对比，人审不迁移为新版通过。

```powershell
python cli.py --workspace F:/clips-work rehearsal build --spec F:/clips-work/private-context/rehearsal.json --task-id draft-01
python cli.py --workspace F:/clips-work rehearsal check --package F:/clips-work/outputs/reviews/rehearsals/draft-01
python tools/serve_review.py --card F:/clips-work/outputs/reviews/rehearsals/draft-01/index.html --port 8765 --nested
```

最后一条仅在本机启动只读预览，允许访问这个交付目录内的子审片卡，禁止目录列表、工作区外路径和写入请求。浏览器打开显示的本机地址。不要把服务根目录设为整个工作区或素材目录。

## 一包里应有什么

| 内容 | 用途 |
| --- | --- |
| `index.html` | 选款说明、完整视频、封面文案、选段时间、分项状态和原速问题入口 |
| `draft-video.mp4` | 带未核词字幕和待审标记的完整视频，1080×1920、30 fps |
| `draft-subtitle.srt` / `.ass` | 可检查的机器原话和对应时间；不是已核准字幕 |
| `cover-3x4.jpg` / `cover-4x3.jpg` | 真实原片帧及待审封面文字 |
| `title.txt` / `caption.txt` / `hashtags.txt` | 待核实文案字段，方便本地交接 |
| `review-*/index.html` | 独立原速问题、时间点和自然语言反馈入口 |
| `rehearsal.json` / `simulation.json` | 原片与输出指纹、时间映射、技术结果、待审状态及本地模拟检查 |
| `quality.md` / `quality.json` | 可读的技术检查与待审内容清单，各项独立记录 |

发帖演练只核对文件和字段齐备、实际媒体可解码、封面可显示及输出保持一致，展示“视频＋封面＋正文＋话题”的本地预览。固定状态为 `SIMULATED_NOT_SUBMITTED`，`uploaded=false`、`submitted=false`、`platform_ui_verified=false`。没有登录平台、真实上传、挂车、排期或点击发布；不能将它称为真实后台已验证。

## 复核和恢复

Codex 应实际打开交付页、播放视频、检查字幕与封面，并逐一验证原速问题能定位。工具只能看抽帧或取得 ASR 时，明确记录能力限制，不声称连续观看或已听清。先完成至少一款真实验收，再扩大覆盖；更多待审视频不能替代一个验收闭环。

收到反馈先原样保存，用 [听审卡反馈流程](human-review.md) 绑定版本、范围和指纹。字幕、原片、速度、剪口或文件变化后，旧包保持原样，创建新的任务版本，重核受影响内容和最终视频。偏好或“继续优化”不是通过；无法确定的词仍是未知。

`check` 会拒绝输入、输出或状态变化，不覆盖旧包。中断或失败目录保留现场，检查错误后使用新 `task-id` 重建。若旧包只因程序版本改变失效，保留其构建证据，不能把旧测试结果当当前代码的验证结果。真实核词、同款和最终听看通过后，再按正式制作链交付；不得把演练包复制成正式包或写假审批接续。
