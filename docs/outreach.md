这是未发布的内容草稿和验证办法，不是已经取得流量、咨询或收入的报告。当前公开状态只看 [release-status.md](release-status.md)。真实客户素材与截图须另有公开依据；不因写好案例就上传视频、发送招募或公开商家信息。

首轮服务对象固定为 Windows、会用 Codex、处理中文单场单款的女装电商运营。交付形态是完整项目与项目内 Skill；`basic` 保留，但不据此宣称已适配全品类。先验证安装、配置、适配和交接服务的付费需求，不先开发软件 UI、账号或平台自动发布。

## 内容一：约一分钟切片从字幕改剪到本地交付的案例

**标题：同一条56秒女装直播切片，怎样减少字幕闪跳？**

> 一条真实开衫原片的待审切片，变速后为56.03秒。前版已经有重点词放大、变色和粗体，但40条机器字幕中，16条显示不足1.2秒；句子跳得太快，重点词也不容易读完。
>
> 新版保持同一原声、选段顺序、速度和时长，只整理字幕显示：在同一剪口与原声窗口内合并紧邻短段，并按实际字号平衡两行。显示字幕从40条减少到25条，不足1.2秒的段降为0；每个原机器段的文字和时间仍保留，未猜改疑词。
>
> 新旧版并排播放，具体问题可以直接回到对应原速小段。本次实际核对了长句、重点词及结尾抽帧，没有在这些样本中看到越界；完整视频可播至结尾，分段按钮能定位并暂停。它们验证了显示和播放操作，不能证明每个字准确或整片听感合格。
>
> 2026年10月20日，用户明确反馈已完整看听、核对原速片段，并确认字幕和同款无误，整体可以接受。我们把原话绑定到实际版本和保留区间，再通过通用交付入口从原片窗口重新制作。无字幕剪辑重建一致，音频逐比特一致，字幕正文与时间不变，只移除待审水印，并补齐有原话依据的双比例封面和文案。
>
> 正式本地包包含视频、字幕、封面、文案、来源、变化说明和质量记录，浏览器实际完整播放通过。原用户确认只覆盖其看过的内容，新画面及封面另行检查；没有把新文件伪记为用户已再次看过，也没有上传到平台。这是首条已审内容的本地交付验证，不是三位外部运营试用，更没有成交增长或节省工时比例的数据。

数字只描述这一条内部样片，不是所有商品的默认片长或字幕标准。没有测量节省工时、成交或平台效果；不能从字幕条数减少推导收益。公共仓库只提供方法和文字记录，商家原片、截图与私人路径不随文稿公开。

### 历史短片案例：A4与A5

**标题：一条 17.03 秒女装直播待审稿，为什么还要分四处回听？**

> 内部女装原片试作中，我们从 A3 的 18.600 秒继续精修到 A4 的 17.033333 秒。这次删去一整句重复解释，四段统一为 1.3 倍，补入同期腰部近景，结尾换用同一原片的退后转侧身画面，并留下 0.6 秒无声定格。
>
> 可播放的对比比“这段应该更紧凑”更容易判断，所以我们同时保留前版、标注每段作用，并把四个问题各自配上未加速的原片小段。你可以先判断节奏，再对照原速核词，而不必重新听整场。
>
> A4 仍是待审稿。机器识别有疑词，原话、同款判断和最终加速听感尚待确认；材料近景和侧身结尾含非同期画面，口型可能不一致。指定原片范围也没有完整裙摆或连续走路展示。
>
> 后续将同一思路迁入通用制作入口，生成 A5 待审预览：去掉突兀的局部放大，保留上身动作与闭口侧身收尾。逐段按帧取整后为 16.83 秒；仍保留原声核词、同款和最终听感的独立待审状态。通用流程随后补齐编辑时间轴到字幕、封面和文案交付的衔接，并用明确标注的合成素材验证程序，不把合成测试称为真实业务验收。
>
> 这次案例说明的是如何把剪辑判断和待审问题交给运营看清楚。导出和技术检查没有证明字幕全对，也没有证明节省了多少工时、提高成交或获得平台表现。下一步是拿真实反馈修订，再让独立运营用自己的素材验证。

案例事实依据为内部 A3/A4 对比说明、A5 通用预览的实际时间线及画面/技术复核；本公共文档不附私有路径、商家名、原片或未获公开授权的截图。上述数字只属于该内部实验，不是默认模板的强制片长、倍速或定格参数。案例文稿能否公开，与媒体素材能否公开分开确认；发布时若审核状态改变，应按对应版本更新正文。

建议配图只在取得授权后使用：两版同尺寸并排、每段作用标注、一个带明确时间点的原速核词卡。没有授权时使用通用流程示意，并显著写“示意”，不能用生成商品图冒充真实案例画面。

## 内容二：首次安装教程草稿

**标题：女装运营第一次用这套本地切片 Skill，需要准备什么？**

> 你需要完整项目文件夹、64 位 Windows、Python 3.12、FFmpeg/FFprobe、本地 small 转写模型和可显示中文的字体。不要只复制一个 SKILL.md，也不要拿别人电脑的虚拟环境直接套用。
>
> 第一步，按安装说明新建独立虚拟环境并安装固定依赖。第二步，把工具、字体和模型的真实路径写入独立商家工作区。第三步运行 doctor，再用原片中的 30–60 秒窗口验证转写与媒体输出。
>
> doctor 通过只说明基础环境齐全。字幕有没有缺字、机器词是否准确、剪切有没有截断原声，还要看真实输出、听原速片段和最终速度成片。第一次不要直接跑整场，也不需要连接店铺账号。
>
> 具体安装步骤见项目的“依赖安装”和“快速开始”；出现错误先保留完整错误与当前版本，不要把 unknown 改成通过。当前功能是本地制作与交付，发布由你按自己的审核流程处理。

正文依据 [依赖安装](dependencies.md) 与 [快速开始](quickstart.md)，公开发布时替换为这两页的真实公开链接。未建立公开地址前不填示例域名。教程中的下载、安装和模型准备要与日常本地运行分开讲清。

## 内容三：选段、字幕与验收 FAQ 草稿

**标题：能导出视频，为什么还不能说“剪好了”？**

| 运营常问 | 可直接使用的回答 |
| --- | --- |
| 能一次自动切完整场、保证出多少条吗？ | 当前一次聚焦一款商品，条数取决于完整表达和真实商品证据；可能只有一条，也可能为零。局部 test 不代表整场盘点。 |
| 女装为什么要确认至少 20 秒？ | apparel 对已确认同款原片区间并集设此门槛；它不是成片最短时长，也不是足够 20 秒就能忽略内容完整性。 |
| 字幕听不清可以让 AI 猜成通顺句吗？ | 不可以。保留疑词和原速片段，给出准确时间点，由实际听过的人反馈；确认不了时保留待审或删掉相应完整表达。 |
| 用户说“我更喜欢 A 版”就算通过吗？ | 只算版本偏好。原话、同款、最终速度听看和用户验收须分别记录。 |
| 为什么还要听加速成片？ | 原速核词不能证明加速后的切口、语气和衔接自然。最终交付文件需要整片连续听看。 |
| 可以拿旧成片补一段吗？ | 新制作只取原片或有原片映射的原始窗口；旧成片保留作比较，不能冒充新制作源。 |
| 转写是本地的，是否所有内容都离线？ | 转写和媒体程序用本地资源运行；AI 宿主接收哪些文件和信息取决于其设置，不能据此承诺整个助手离线。 |
| 能自动上传、挂车、排期吗？ | 首版没有这些执行入口。它交付本地成片、字幕、封面、文案和质量记录。 |
| 这是剪映替代品或有完整操作界面吗？ | 当前是完整仓库与 Skill 的工作流，面向能用 Codex 操作文件的运营，没有完整图形剪辑界面。 |
| 有节时、播放量或成交证明吗？ | 只有真实试用与实际业务数据才能回答。当前不预填节时或收益，试用会记录安装、求助、失败、改片和复用工时。 |

具体审核方式见 [听审说明](human-review.md)；首次运行见 [快速开始](quickstart.md)。

## GEO：把“AI 会不会正确找到并描述”当实验

这里的 GEO 指检查 AI 回答是否发现、引用并正确描述项目，不承诺排序或推荐。资料正式公开且有真实可访问 URL 后才进行公开可发现性实验；本地未公开候选不能算被互联网检索到。

固定以下问题原文，建立基线后不为迎合结果临时换问法：

1. 我在 Windows 上用 Codex，想把一场中文女装直播里的一个商品剪成原声短视频，有哪些本地工作流可选？
2. 有没有保留原片时间映射、能让我逐句核对字幕的女装直播切片 Skill？
3. 女装直播切片怎样确认同款、处理听不清的字幕，并保留待审记录？
4. 这类本地女装切片工具首次安装需要准备哪些依赖，适合什么样的运营？
5. 我想找人帮我安装配置并交接本地女装直播切片流程，应该怎样判断交付是否完成？

每轮固定同一模型/版本、同一联网或搜索模式、相同可用地区与语言设置。每题至少在 **3 个全新、无前文的新对话** 分别采样，不用已有介绍项目的对话，不把第一次答案复制进下一次。模型或模式变化时另开组，不和旧组直接合并。保存日期、问题原文、模型、模式、完整回答、引用 URL 和判断依据。复测采用同一规则，不能挑选只有正面结果的回答。

回答发现项目后，逐项检查“适用人群、Windows/Python、本地模型、完整仓库、人工听审、无自动发布、当前验证边界”是否准确。名称出现、被引用与被推荐分别记录；缺失和错误也计入分母。引用真实性和项目相关性都要检查，不把虚构链接计成有效引用。

| 层级 | 怎么记 | 不能混为一谈的事 |
| --- | --- | --- |
| 引用 | 有至少一个真实项目来源引用的回答数 / 有效采样回答数；另记仅提名次数 | 被提名不等于被引用，更不等于用户访问 |
| 准确性 | 已核对关键事实数、正确数、错误原句；另记严重错误回答数 / 采样数 | 引用真实不代表描述正确 |
| 访问 | 真实页面访问及来源；只用已启用且获准使用的统计或自报来源 | 模型内点链接、重复刷新、爬虫不算有效咨询 |
| 有效咨询 | 去重咨询，确有目标女装场景与素材/环境问题，愿意讨论实际服务范围 | 点赞、下载、泛问和安装报错不自动等于购买意愿 |

验收以对方能找到工作区、运行环境检查、读懂待审项、看听对应版本，并在新素材上重复操作为准。一次真实付款及完成交付只能说明首个订单成立；继续记录实际人工工时、返工和售后，再判断服务是否值得重复。价格由实际范围与试用数据确定，此处不编造市场价或收入预期。
